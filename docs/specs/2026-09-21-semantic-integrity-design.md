# M59 语义完整性修复

> 状态：approved。授权：2026-09-21 用户在对抗性审核与结构性分析后明确要求「根源性的问题你直接处理」。本文件细化该修复，不授权提前启用 M59-2 页面身份或迁移 Grafeo。

## 契约

1. 表达式的引用出现位置与去重后的依赖集合分离。引用出现记录保存原始 token、UTF-8 字节区间和解析目标；替换只作用于原表达式上的区间，不扫描已插入的内容。
2. 属性路径完整保留；`.step` 与嵌套属性不伪装为值引用。解析、追溯与扫描共享语义。递归栈只检测当前调用链的循环，重复引用与菱形依赖不能被截断。循环、深度限制、缺失定义和不支持语法须显式报告部分完成。
3. 成功构造的页面身份必须可往返解析；不支持的保留分隔符显式拒绝。项目身份仍由单项目 store 边界承载，M59-2 启用时必须校验项目绑定；本批不启用新页面 ID。
4. 关系与证据分离：同端点、类型、字段但不同 metadata 的边是不同事实，不再静默丢弃后写证据；完全相同事实幂等。memory/redb/dense/v2 采用同一事实键，持久化编码须无分隔符歧义。
5. 事实键升级不与旧库混写：旧事实键的非空库拒载并说明重建；重建从原始元数据重新生成，不能从已经丢失证据的旧图推断事实。此版本仅标记事实表示能力，不代表 M59-2 的 ownership/schema 工作完成。

## 验收

用手工期望与变形测试约束混合引用、重复引用、菱形、循环、深度、完整属性路径、中文与字面量、优先级、ID 碰撞/往返、事实幂等/排列无关/重启持久化。不得只用双后端相等或 full==incremental 代替语义正确性。测试仅 CNB 远端执行。

## 边界

M59-2 的按 origin 撤销、共享目标生命周期、项目绑定与新页面 ID 启用仍按原批准计划独立交付；B5 缺陷不随本批关闭。F3 完整表达式语言、F5/F6、三动词 adapter、Grafeo 不在本批。

Baseline impact: yes。引用出现位置与完整事实保留改变解析成本及边数；不声称真实语料性能改善，历史基线不可直接作本批性能验收。

## M59-2 必须消费的归属契约

- **实体身份**：项目绑定 + 归一化源文件 + 局部名；物理实体的全局仅指同一项目 store。项目绑定必须在打开已有 store 时核验，不能把某台机器的绝对目录当跨环境身份。
- **事实身份**：本批完整事实键是信息无损的基础；后续 source-file/json-path/属性路径构成稳定来源标识，metadata 是其证据载荷。不同来源不能因端点相同而折叠；同来源变更必须撤销旧版本。
- **来源撤销**：一份文件可以贡献实体定义、目标引用和边；共享实体的定义者与多个引用者分别记账。替换文件只撤销该来源贡献，不能按端点级联删除其他来源的边。
- **共享目标生命周期**：有定义则按定义展示；无定义但仍被引用则退回占位；定义与引用均消失才回收。两个不兼容定义必须报告冲突，禁止扫描顺序决定结果。
- **原子性**：候选贡献、派生图、文件 hash、diagnostic 和 refresh checkpoint 一起提交。解析失败保留旧贡献并保持脏；失败不得推进 checkpoint。
- **验收**：修改/删除定义者、删除任一引用者、删除最后引用者、占位升级/降级、扫描顺序交换、重启和坏文件恢复，都须匹配独立的预期事实；再要求 full==incremental（全部属性和重复次数）。

这些是下一包的实施约束，当前代码没有实现来源撤销。`fact_schema_version=2` 只证明采用完整事实键，不等于 ownership 或页面局部身份已启用。
