# 知识库验收集（不入库）

> 本目录**故意不被知识库索引**。它包含知识库验收的问题、期望答案与实测记录，
> 一旦入库，检索命中就是「用答案验答案」，验收结论失去意义（Issue #30 复审 P1）。

## 为什么单开一个目录

`docs/knowledge/**` 是唯一被索引的白名单语料目录。验收材料必须与它物理隔离：

- 问题集 + 期望答案 + 实测记录都在本目录；
- `.cnb.yml` 的 `.knowledge_base_ci` 用显式 `include` 白名单，同时在 `exclude` 里
  再加一条 `docs/knowledge-acceptance/**` 作兜底，避免以后放宽 include 时误收；
- 验收时要能证明「空上下文 agent 只看得见被索引的内容」，所以本目录内容
  对 agent 不可见是**验收前提**，不是缺陷。

## 验收方式

1. 每次重建知识库后，用**空上下文 agent**（无本仓库文件访问权限，只能检索知识库）逐题提问。
2. 查询串必须是**原始问题口径**，不得抄录本目录里的「期望答案要点」原词——
   抄原词等于把答案喂给检索器。
3. 每题记录：召回的 top chunk（文件 + position + 分数）、**agent 的原话回答**、
   是否正确、是否需要修条目。只记「命中了某个 chunk」不算通过。
4. 分别检查**检索失败**（召回不到应有条目）、**条目误导**（例如把计划写成实现）
   与**回答误推断**（片段正确，但回答移接了主体、条件或处理层）。三者可能同时存在；
   检索命中或安全回答「未知」都不能独自证明问答通过。
5. 反误导题（⚠C）答错即不通过；边界题（D）必须答「未知 / 未在知识库中」并停止推断。

## 判定

- ⚠C 类全部答对、D 类能停止推断 → 可考虑扩展主题。
- ⚠C 类任一答错 → 暂停扩展主题，先对照源码、原始检索和完整回答定位错误来源。
  源码证实条目错误才修语料；片段正确时固定输入诊断回答；未召回时固定索引诊断查询。
- D 类被编造答案 → 检查是否缺少范围说明，或模型越过已有说明；不能直接认定需要补语料。
  片段未描述某能力或缺陷，不等于源码或计划中不存在它。

## 可重放验证（PR33）

`questions.json` 冻结 24 道固定题及 8 道改写/新题。H1–H3 直接针对本次发现的错误，
其余用于检验同一主题的不同问法；这是开发者设计的小样本，不是外部盲测。
题集中只有问题，答案键仍保留在历史表和人工评审报告中，均不发送给回答模型。

**术语口径（PR33 起强制区分）**：

- **验收**：题目在提问前从未用于修改语料，且运行前冻结 → 结果可称为验收。
- **回归**：题目已经参与过文档/提示词修正（本目录第 2 轮及以后所有运行均属此类）→
  结果只能称为回归证据，**不得**写成「验收通过」。
- 同一题一旦参与修复，永久降级为回归题，不再回到验收口径。

1. 提交并推送修正文档，以该完整 SHA 单次 `forceRebuild`；日常配置保持 false。
2. 检查 `last_commit_sha` 与白名单，再在同一 SHA 触发 `api_trigger_knowledge_acceptance`。
3. 流水线先跑 shell/评测器回归测试，再运行 `scripts/kb-evaluate.py`。每题独立
   HTTP 请求，仅有统一 system prompt、该题和其 top-k=5 片段，无历史消息或工具权限。
4. 用 `cnb build build-runner-download-log --repo wu2305/metadata-checker
   --pipelineId <sn>-001 --verbose` 将完整日志 JSON 保存到临时文件，再运行
   `python3 scripts/kb-extract-evidence.py <日志.json> <run.json.gz>`。
   stage 详情接口会截断超过 100 KiB 的日志，不能用它取完整产物。
   解压产物后可检查完整请求、响应、原始检索、模型和索引 SHA。
5. `captured_pending_manual_review` 只表示采集完整；人工逐题记录 pass/partial/fail
   及理由，反误导题错误或边界题编造均阻止知识库验收，不把脚本退出 0 当全答对。

流水线中的模型默认为 `deepseek-v4-flash`，返回的实际模型字段另行记录。重放时
使用新输出路径；索引在运行前后必须一致。不要把完整异常或认证头写进产物。
评测完成后若只提交不入库的报告，须比较所有索引文件的 Git blob，证明与已验证
索引版本一致，不能把不同 SHA 直接称为同一版本。
